# 017 · ปุ่ม Clear line ของ PowerShell บางครั้งไม่ลบบรรทัด (Esc ตัวเดียวกำกวมใน ConPTY)

- วันที่: 2026-10-11
- tags: terminal, test
- project: ทุกโปรเจกต์ (เทสต์ `tests/react-shell.test.mjs` "Insert bar types context … Clear line empties it")

## ปัญหา
ในการรัน `npm test` ชุดเต็มครั้งหนึ่ง เทสต์ล้มด้วย `page.waitForFunction: Timeout 8000ms exceeded` ที่ขั้นหลังกด Clear line บรรทัด prompt ไม่ว่าง แต่รันเดี่ยวผ่าน 4/4 และชุดเต็มรอบถัดไปก็ผ่าน ผู้ใช้จริงก็น่าจะเจอได้ คือกด Clear line แล้วบางครั้งข้อความไม่หาย

## สาเหตุ
น่าจะเป็นเพราะ `InsertBar.tsx` ส่ง ESC ตัวเดียว (`\u001b`) ให้ PSReadLine ทำ RevertLine แต่ ESC ตัวเดียวเป็นค่ากำกวมใน VT input ของ ConPTY เพราะเป็นทั้งปุ่ม Esc และตัวแรกของ escape sequence ConPTY ต้องเดาจากจังหวะที่ข้อมูลมาถึง ตอนเครื่องทำงานหนักจึงอาจรอ ESC ไว้หรือตีความผิด (สรุปจากการอ่านโค้ด ยังไม่ได้ทำให้เกิดซ้ำ)

## วิธีแก้ที่ได้ผล
- เปลี่ยนสิ่งที่ส่งเป็นรหัสปุ่มครบชุดที่ไม่กำกวม: End (`\x1b[F`) แล้ว Ctrl+Home (`\x1b[1;5H`) ซึ่งเป็น BackwardDeleteInput ของ PSReadLine ลบตั้งแต่ cursor ถึงต้นบรรทัด ผลเหมือนเดิมและไม่มีอะไรถูกรัน
- ตรวจแล้ว: เทสต์ตัวนี้รันเดี่ยวผ่าน 5/5, `ui:check` exit 0, `npm test` ชุดเต็มผ่าน 80/80 (เทสต์ที่ล้มเป็นบางครั้งพิสูจน์ไม่ได้ 100% ด้วยไม่กี่รอบ ถ้าล้มอีก ให้ `ref:` มาที่ไฟล์นี้)
- บทเรียน: ตอนหาสาเหตุ อย่าสร้างโหลด CPU เทียมบนเครื่องผู้ใช้ ครั้งนี้เกือบทำให้เครื่องค้าง ให้อ่านโค้ดก่อน แล้วรันเฉพาะเทสต์ตัวนั้นทีละรอบ
